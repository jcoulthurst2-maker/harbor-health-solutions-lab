## What I am building

This track moves from analysis into **making systems do something**.

The goal is to become comfortable writing Python that can transform data, call external services, handle failures, and connect multiple steps into a dependable workflow.

## Core capabilities

- Python fundamentals and clean program structure
- variables, functions, collections, loops, and conditionals
- reading and writing files
- data transformation and validation
- JSON and structured payloads
- REST APIs and HTTP methods
- authentication patterns
- pagination and rate limits
- error handling and retries
- logging and basic testing
- automation scripts
- small service and integration builds

## How the Lab trains it

The mission format turns Python and API work into operational problems rather than generic coding prompts.

A mission might require pulling information from multiple fictional services, normalizing inconsistent responses, detecting a missing dependency, or building a small automation while conditions continue to change.

The important question is not only **“does the code run?”** It is also whether the automation is safe, understandable, resilient, and appropriate for the decision being made.

## Progression

### Foundation
Write small Python programs, manipulate structured data, work with files, and understand common errors.

### API fluency
Send requests, work with JSON, authenticate, inspect responses, handle pagination, and recover from expected failures.

### Integration work
Connect multiple services, transform payloads, validate inputs and outputs, and preserve useful logs.

### Small systems
Build lightweight services and automation flows with clearer boundaries, tests, retries, configuration, and failure behavior.

## What counts as proof

Completed evidence can include:

- Python scripts
- API clients
- integration flows
- test cases
- error-handling examples
- service diagrams
- mission artifacts and postmortems
- short explanations of design choices and tradeoffs
