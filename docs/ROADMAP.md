# 32-Week Global Technical Capability Roadmap

[← Back to Solutions Lab](../README.md)

This roadmap is built around one outcome: become increasingly deployable in roles that sit between engineering, implementation, data, AI, customers, and business outcomes.

The curriculum is not organized around “cool projects.” Each phase maps to work hiring teams actually pay Solutions Engineers, Technical Implementation teams, Forward Deployed teams, AI Solutions teams, and transformation consultants to perform.

## Weeks 1–8 · SQL + Data · Tokyo
### Enterprise Deployment Rescue
Build fluency in querying, joins, aggregation, metric definitions, data quality, adoption analysis, and evidence-based implementation diagnosis.

**Scenario:** a strategic SaaS customer is late across four business units and 18 days from renewal. Separate integration defects, configuration debt, and adoption failure, then build a 14-day recovery plan.

**Employer signal:** use data to diagnose a deployment and make a bounded customer recovery decision.

## Weeks 9–14 · Python + APIs · Nairobi
### Payments API Reliability
Move from analysis into code, automation, structured data, REST APIs, validation, normalization, retries, idempotency, error handling, and observability.

**Scenario:** a mobile-money partner API changed and payment failures doubled.

**Employer signal:** make an integration reliable when the happy path stops being reliable.

## Weeks 15–19 · Data Systems · London
### Enterprise Migration Cutover
Work with canonical schemas, identity mapping, pipelines, lineage, validation, reconciliation, quarantine, rollback, and cutover gates.

**Scenario:** a legacy CRM and target platform disagree about customer identity, status, and ownership.

**Employer signal:** treat migration as an operating cutover, not just an ETL exercise.

## Weeks 20–24 · Cloud + Architecture · Trinidad
### Regional Logistics Platform
Design compute, databases, queues, workers, observability, reliability, fallback, recovery ownership, and proportional cost.

**Scenario:** a synchronous carrier dependency is creating cascading dispatch delays across a regional logistics operation.

**Employer signal:** design architecture around real continuity requirements rather than résumé complexity.

## Weeks 25–28 · AI Systems · Global
### Production AI Rollout
Work with task definition, retrieval, failure sets, evaluation, abstention, tools, human authority, observability, adoption, and rollback.

**Scenario:** the AI demo performs well but rare failures are expensive and users do not trust it.

**Employer signal:** move AI from demo quality into a governed production workflow.

## Weeks 29–32 · Implementation · Multi-region
### Enterprise Go-Live
Bring the technical work into workflow discovery, requirements, UAT, readiness, rollout, support, adoption, containment triggers, executive communication, and value verification.

**Scenario:** Tokyo, London, Nairobi, and Port of Spain are technically live at different levels of stability and adoption.

**Employer signal:** carry technically sound work all the way into a functioning operating reality.

## What changes across the 32 weeks

The guidance decreases. The systems become more connected. The data becomes less clean. Failure handling matters more. Business context becomes less optional. The expected output shifts from “correct technical answer” toward “credible deployment decision.”

The evidence standard also increases:

**L0 Drill → L1 Employer Simulation → L2 Production Analogue → L3 External Deployment**

The objective is not to collect tools. It is to expand the amount of an unfamiliar technical deployment I can understand, build, recover, and defend independently.

Completed evidence is added only after the underlying work has actually been completed.
