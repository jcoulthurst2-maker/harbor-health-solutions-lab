# Solutions Lab v2 — 26-Week Global Technical-Business Apprenticeship

## North Star

Develop the ability to enter an unfamiliar organization, understand what matters, establish reality, diagnose a complex problem, work across business and technology, design and build an appropriate intervention, operate it, and prove whether value was created.

The Lab is not organized around becoming an implementation specialist, cloud engineer, data analyst, or AI specialist. Those are lenses and capabilities inside a broader professional formation: a globally deployable technical-business problem solver.

## Governing Doctrine

1. Real problems over toy exercises.
2. Mastery over completion.
3. Guidance decreases as capability increases.
4. Problems drive capability acquisition, not the reverse.
5. The client’s diagnosis is evidence, not truth.
6. Technical success is insufficient without business value, adoption, reliability, security, and economics.
7. No capability becomes Independent through explanation alone.
8. Portable concepts are assessed even when vendor-specific technologies are used.
9. Professional reviews produce improvement actions, not decorative scores.
10. Old decisions return later so the learner experiences how judgment ages.

## Professional Lifecycle

DISCOVER → FRAME → ESTABLISH REALITY → DIAGNOSE → GENERATE OPTIONS → EVALUATE TRADEOFFS → DESIGN → BUILD / INTERVENE → VALIDATE → DEPLOY / OPERATIONALIZE → OBSERVE → MEASURE VALUE → IMPROVE → TRANSFER

## Apprenticeship Stages

### Weeks 1–4 — Observe + Assist
The master practitioner narrates attention, demonstrates problem framing, explains why certain evidence matters, and opens just-in-time technical skill chambers when required.

### Weeks 5–9 — Guided Operator
The learner increasingly chooses the investigation path. The mentor asks questions and challenges assumptions rather than prescribing steps.

### Weeks 10–14 — Co-lead
The learner frames problems, proposes technical and nontechnical interventions, and defends tradeoffs. Mentor input becomes selective.

### Weeks 15–19 — Lead
The learner owns the engagement path. The mentor acts mainly as reviewer and intervenes only around material blind spots.

### Weeks 20–23 — Independent Practice
The learner operates with minimal support and can request consultation, mirroring strong professional practice.

### Weeks 24–26 — Capstone Assessment
No teaching during primary execution. Post-engagement professional review only.

## 26-Week Operating Map

### Month 1 — Learning to See
- Week 1: Aster Systems activation failure — shadow the full problem-solving cycle; SQL appears just-in-time.
- Week 2: Aster Systems deeper evidence — connect account, provisioning, product, and commercial evidence.
- Week 3: Capacity mystery — Python/data cleaning; test whether headcount is actually the constraint.
- Week 4: Transfer challenge — new industry, same reasoning, fewer cues.

### Month 2 — Systems Talk to Systems
- Week 5: Integration breakdown — APIs, JSON, authentication, webhooks, logs, data contracts.
- Week 6: Automation decision — rules vs workflow vs software vs AI; ROI and controls.
- Week 7: Integration challenge — no procedural instructions; diagnose an unfamiliar API failure.
- Week 8: Return to Aster — inspect how earlier decisions aged and what consequences emerged.

### Month 3 — From Fixing to Designing
- Week 9: Product adoption — analytics, interviews, experimentation, product and commercial judgment.
- Week 10: Scaling system — compute, storage, networking, queues, databases, observability.
- Week 11: Architecture review — AWS/Google quality lenses; reliability, performance, cost, security tradeoffs.
- Week 12: Build + validate — deploy a working high-fidelity solution and verify behavior.

### Month 4 — Integrated Operator
- Week 13: APAC regional expansion — Singapore-led multi-market problem spanning latency, data, operations, economics, and regional constraints.
- Week 14: Production AI system — use-case selection, retrieval/tools, evals, governance, human escalation.
- Week 15: AI architecture + security — NIST AI RMF, secure AI architecture, application/API controls, cost.
- Week 16: Independent integration review — mixed-domain engagement; mentor moves to reviewer.

### Month 5 — Operate Under Reality
- Week 17: Enterprise transformation — legacy systems, vendors, incentives, governance, operating model.
- Week 18: Production incident — SLOs, monitoring, rollback, incident command, postmortem.
- Week 19: Reliability follow-through — error budgets, capacity, recurrence, improvement plan.
- Week 20: Constrained-market system — architecture under different infrastructure and economic assumptions.
- Week 21: Return engagement — reassess an earlier organization under changed conditions.

### Month 6 — Global Independent Practice
- Week 22: Multinational architecture — multi-region, multi-cloud, build/buy, resilience, lock-in, cost.
- Week 23: Adversarial review board — defend decisions to engineering, finance, security, product, and executives.
- Week 24: Capstone discovery — unfamiliar organization, no prescribed technology, incomplete problem statement.
- Week 25: Capstone execution — build/intervene, validate, operationalize, measure.
- Week 26: Capstone consequence — reality changes; adapt, review, publish evidence, and complete transfer assessment.

## Capability Levels

- Observed — has watched expert execution and can explain the purpose.
- Assisted — can perform with direct support.
- Guided — can perform with questions/review but without prescribed steps.
- Independent — can execute without instruction in a known class of problem.
- Transferable — can execute in an unfamiliar domain or system.
- Adaptive — can maintain sound judgment when requirements, constraints, or reality change.

Graduation aims for Independent + Transferable across the core capability set, with selected domains reaching Adaptive.
