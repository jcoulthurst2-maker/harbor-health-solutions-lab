# Why These Problems

Harbor Health is designed around healthcare problems that force operations, data, technology, and implementation to work together.

- **Appointment access** — proves whether the real issue is scheduling, staffing, referrals, capacity, or data.
- **Data trust** — prevents dashboards, automation, and AI from confidently using bad information.
- **Prior authorization** — combines payer rules, documentation, manual work, technology, and human judgment.
- **Fragmented systems** — reflects how healthcare work moves across EHRs, vendor tools, spreadsheets, portals, and internal systems.
- **FHIR / HL7** — teaches not just how systems connect, but how healthcare information keeps consistent meaning.
- **AI** — teaches when AI adds value, when it does not, and how to keep people in control.
- **Security and continuity** — makes failure, permissions, logging, recovery, and safe operation part of the design.
- **Implementation and adoption** — recognizes that a technically correct system can still fail if people will not use it.

## Design rule

A mission is not created because it is “time to learn Python” or “time to learn AWS.”

A mission exists because Harbor Health has a believable problem, and the technology is introduced because that problem requires it.
